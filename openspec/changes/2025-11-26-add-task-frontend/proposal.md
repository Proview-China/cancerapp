## Why
- 需要一个与现有视觉和交互一致的任务中心，统一承载上传/自动分析/审核/训练/预测/报告等任务的查看与管控，避免分散在病例流之外。
- 后端接口/数据库可能暂未就绪，前端必须先用一致的数据形状提供 demo，且预留与真实 API 的无缝切换，保证 UI 交付不中断。
- 任务状态/类型枚举、日志/进度展示、导出占位、权限与操作约束需要在规格层面先锁定，避免前后端各自定义导致行为不一致。

## What Changes
- 新建“任务中心”前端能力：Dashboard（统计/预警/进度管线/动态）与任务列表+详情（步骤、日志分页、模型版本、数据源、ETA、导出占位、操作）。
- 定义任务数据模型与接口契约：状态 `queued|pending|in_progress|done|failed|paused|canceled`，类型（上传、自动分析、审核、训练、预测、报告、数据标注），列表/详情/日志分页、停止/重跑、导出占位，字段采用 snake_case，前端映射 camelCase。
- 前端内置 demo 任务数据（列表+详情+日志），在 `taskService` 提供 `USE_DEMO_TASKS` 开关，API 形状与后端保持一致，后续仅切换数据源。
- 刷新策略：无推送时对 `queued|in_progress|paused` 任务 10–15s 轮询列表与详情，结束态停止；日志用分页/增量；导出下拉占位 pdf/json/excel，未开通提示。
- 权限/操作约束：按钮显隐/禁用依据角色能力（建议 Admin 全权、责任人可控自身任务，System 任务仅 Admin），且遵循状态约束（运行中可停，完成/失败可重跑，待处理可开始），后端需同步校验。

## Impact
- Specs：新增任务中心能力，覆盖状态/类型枚举、数据形状、接口契约、轮询/日志分页策略、权限/操作约束、导出占位、demo/真实数据一致性。
- Code：规划新增 `taskService`（带 demo 开关）、任务类型定义、任务中心 UI；复用既有色板/排版；病例流保持不变。
- 验证：规格通过 `openspec validate`，并预留后续实现时的 UI 渲染、轮询启停、日志分页、操作显隐、导出占位与空/错误/队列态的走查。
